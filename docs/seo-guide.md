# 열정상회 검색 노출 가이드

홈페이지가 네이버·구글·다음 검색과 AI 검색(네이버 AI 브리핑, 구글 AI 개요, 챗GPT, 클로드, 퍼플렉시티 등)에 잘 노출되도록 하기 위한 운영 안내입니다.
사이트 안의 기술적인 준비는 되어 있습니다. 아래는 무엇이 준비되어 있는지와, 사람이 해야 하는 일입니다.

**먼저 할 일 다섯 가지** (효과가 큰 순서)

1. 네이버 서치어드바이저에서 소유확인을 마치고 사이트맵과 RSS를 제출합니다. (2번 항목)
2. 구글 서치 콘솔에 등록하고 사이트맵을 제출합니다. 빙은 구글 서치 콘솔에서 가져오기로 등록합니다. (2번 항목)
3. Cloudflare에서 AI 검색 로봇을 막고 있지 않은지 확인합니다. (8번 항목)
4. 네이버 블로그를 열어 상회보 글의 요약을 올리고 홈페이지로 연결합니다. (5번 항목)
5. 글을 올리거나 고친 날에는 관리자 화면 상회보에서 **검색엔진에 알리기**를 누릅니다. (9번 항목)

## 2. 공개 직후 할 일 (순서대로)

### ① Cloudflare 빌드 설정 확인

Cloudflare → Workers & Pages → 이 프로젝트 → Settings → Builds

- Build command: `node tools/build.js`
- Build output directory: `public`

이 설정이 있어야 `site.json`과 상회보 글을 고쳤을 때 사이트에 반영됩니다.

### ② 네이버 서치어드바이저

1. [searchadvisor.naver.com](https://searchadvisor.naver.com) → 웹마스터 도구 → 사이트 등록에 사이트 주소를 넣습니다.
2. 소유확인 방법에서 **HTML 태그**를 고르고, `content="..."` 안의 값만 복사합니다.
3. GitHub에서 `site.json`을 열어 `"naver": ""` 따옴표 안에 붙여 넣고 Commit changes를 누릅니다.
4. 1~2분 뒤 서치어드바이저에서 소유확인을 누릅니다.
5. **요청 → 사이트맵 제출**: `https://주소/sitemap.xml`
6. **요청 → RSS 제출**: `https://주소/rss.xml`
7. **검증 → robots.txt → 수집요청**을 누릅니다.
8. **요청 → 웹 페이지 수집**에 홈, 가입 안내(`/join`), 장날(`/jangnal`), 대상별 페이지 네 곳(`/for/shop-owners` 등)을 하나씩 넣습니다.

### ③ 구글 서치 콘솔

1. [search.google.com/search-console](https://search.google.com/search-console) → 속성 추가 → **URL 접두어**에 사이트 주소를 넣습니다.
2. 확인 방법에서 **HTML 태그**를 고르고 `content` 값만 복사해 `site.json`의 `"google"`에 넣습니다.
3. 확인을 누른 뒤 **Sitemaps** 메뉴에 `sitemap.xml`을 제출합니다.

### ④ 다음 웹마스터도구

1. [webmaster.daum.net](https://webmaster.daum.net)에서 사이트를 등록하면 robots.txt에 넣을 한 줄(`#DaumWebMasterTool:...`)을 줍니다.
2. 그 한 줄 전체를 `site.json`의 `"daumRobotsLine"`에 넣습니다.

### ⑤ 빙(선택)

Bing Webmaster Tools는 구글 서치 콘솔에서 가져오기를 쓰면 따로 확인할 필요가 없습니다. 직접 등록한다면 HTML 태그 값을 `"bing"`에 넣습니다.

> 등록했다고 바로 검색에 나오지는 않습니다. 보통 수집 → 색인 → 노출까지 몇 주가 걸립니다.

## 3. 정식 도메인을 연결할 때

1. Cloudflare Pages 프로젝트 → Custom domains에서 도메인을 연결합니다.
2. `site.json`의 `"url"`을 새 주소로 바꿉니다. (예: `"https://passionstore.kr"`) 끝에 `/`는 붙이지 않습니다.
3. 검색엔진에는 새 주소로 다시 등록하고 사이트맵을 제출합니다.

모든 페이지의 대표 주소(canonical), 사이트맵, RSS가 새 주소로 자동으로 바뀝니다.

## 4. 상회보 글 운영

검색 노출은 결국 글이 쌓여야 늘어납니다. **격주에 한 편**을 목표로 하세요. 상회보 담당 운영진이 맡으면 좋습니다.

### 글 올리는 법 (GitHub 웹에서)

1. 저장소에서 `content/journal` 폴더로 들어가 **Add file → Create new file**을 누릅니다.
2. 파일 이름을 영문으로 짓습니다. 이 이름이 주소가 됩니다. 예: `first-hire.md` → `/journal/first-hire`
3. 맨 위에 아래 앞머리를 붙이고, 그 아래에 본문을 씁니다.

```
---
title: 첫 직원, 언제 뽑아야 할까
description: 검색 결과에 보일 설명. 핵심 키워드를 앞쪽에 넣고 80~110자로 씁니다.
date: 2026-11-23
category: 장사 이야기
keywords: 첫 직원 채용, 자영업자 채용, 1인 사업자 직원
image: packing
---
:::summary
- 이 글의 핵심을 한 문장으로 씁니다. 질문에 대한 답부터 적습니다.
- 두 번째 요점
- 세 번째 요점
:::
```

### 좋은 글의 기준

- 제목에 사람들이 실제로 검색하는 말을 넣습니다. ("첫 직원 채용 시기"처럼)
- 글 맨 위에 `:::summary` 요점 상자를 넣습니다. 세 줄 안팎으로, 질문에 대한 답부터 적습니다. 검색 결과 요약과 AI 답변이 이 자리를 가장 먼저 읽습니다.
- 첫 문단에서 이 글이 무엇을 알려 주는지 바로 말합니다.
- 비교하는 내용은 표로 정리합니다. (줄마다 `| 칸 | 칸 |`, 둘째 줄은 `| --- | --- |`)
- 글 끝에 `## 자주 묻는 질문`을 두고 `### 질문?` 아래에 두세 문장으로 답합니다. 사람들이 검색창이나 AI에 묻는 말투 그대로 질문을 씁니다.
- 숫자와 기준은 정확한 값과 시점을 적습니다. ("많다"가 아니라 "2026년 8월 기준 430만 3천 명")
- 소제목(##)을 3개 이상 둡니다. 글 옆에 차례가 자동으로 생깁니다.
- 통계나 제도는 출처를 글 끝에 적습니다. 지원사업처럼 해마다 바뀌는 정보는 공고 원문을 확인하라고 덧붙입니다.
- 상단에서 나온 이야기를 쓸 때는 당사자 동의를 받고 사람과 회사를 알 수 없게 바꿉니다(헌장 2조).
- 글 끝 안내 상자에서 관련 페이지(대상별 페이지, 프로그램, 장날)로 연결합니다.

장날이 열리기 시작하면 **매달 장날 후기**를 짧게라도 올리세요. "사업자 모임 후기"는 검색하는 사람이 많고, 실제 모임이 열린다는 신뢰를 줍니다. 사진은 찍혀도 괜찮다고 한 사람만 씁니다.

## 8. AI 검색(GEO·AEO)에 대비해 둔 것

요즘은 검색 결과 맨 위에 AI가 요약한 답이 먼저 나옵니다(네이버 AI 브리핑, 구글 AI 개요). 챗GPT나 클로드에 “서울 사업자 모임 추천해 줘”라고 묻는 사람도 늘었습니다. AI는 여러 글에서 답이 되는 문장을 골라 출처와 함께 보여 주므로, **질문에 바로 답하는 문장이 분명한 글**이 인용됩니다.

구글은 2026년 5월에 낸 공식 안내에서, AI 검색을 위한 특별한 비법은 없고 기존의 좋은 검색 최적화(수집이 잘 되고, 도움이 되는 고유한 내용)가 그대로 통한다고 밝혔습니다. 그래서 요령보다 내용을 충실히 하는 쪽으로 준비했습니다.

### 홈페이지에 준비된 것

| 준비한 것 | 어디에 | 하는 일 |
| --- | --- | --- |
| 한눈에 보기 | 홈, 소개 | 열정상회를 한 문장으로 정의하고 여덟 가지 질문에 짧게 답합니다. 내용은 `tools/facts.js` 한 곳에서 고칩니다 |
| 글 머리 요점 상자 | 상회보 글 전체 | 글의 핵심 세 줄. 본문의 `:::summary` |
| 질문과 답 | 자주 묻는 질문(30개), 대상별 페이지, 상회보 글 | 질문 하나에 답 하나. 구조화 데이터(FAQPage)로도 알립니다 |
| 용어 사전 | `/glossary` | 상단, 핫시트, 소상공인 같은 말 29개를 한두 문장으로 풀이. `tools/glossary.js`에서 고칩니다 |
| 구조화 데이터 | 모든 페이지 | 단체 정보(회비 없음, 대상, 지역), 글 정보(요약, 고친 날), 용어, 장날 일정(무료) |
| 수집 로봇 허용 | `robots.txt` | 검색엔진과 AI 검색 로봇(챗GPT, 클로드, 퍼플렉시티, 구글 등)을 모두 허용 |
| AI용 안내 파일 | `/llms.txt`, `/llms-full.txt` | 사이트 요약과 주소 목록, 본문 전체. 빌드할 때 자동으로 만들어집니다 |
| 이미지 사이트맵 | `sitemap.xml` | 페이지마다 대표 그림 주소를 함께 알립니다 |

`llms.txt`는 아직 표준으로 자리 잡지 않았고 구글은 쓰지 않는다고 밝혔습니다. 비용이 들지 않아 넣어 두었지만 큰 효과를 기대할 것은 아닙니다. 효과가 확인된 것은 내용, 수집 허용, 꾸준한 갱신입니다.

### 사실이 바뀌면 고칠 곳

회비, 모임 방식, 지역, 가입 방법처럼 열정상회의 기본 사실이 바뀌면 아래 세 곳을 함께 고칩니다. AI는 여러 페이지를 비교해 읽기 때문에 서로 다른 말이 적혀 있으면 틀린 답을 내놓습니다.

1. `tools/facts.js` (홈·소개의 한눈에 보기, llms.txt)
2. `tools/faq.js` (자주 묻는 질문)
3. `tools/glossary.js` (용어 사전)

### Cloudflare에서 AI 로봇을 막고 있지 않은지 확인하기

Cloudflare는 도메인에 따라 AI 로봇을 기본으로 막아 두는 경우가 있습니다. 한 번만 확인하면 됩니다.

1. Cloudflare → `passionstore.kr` 도메인 → **AI Crawl Control**(또는 Security → Settings의 AI bot 항목)로 갑니다.
2. Search(검색), Training(학습), Agent(대신 열어 보기) 항목이 **Allow**인지 봅니다. Block으로 되어 있으면 Allow로 바꿉니다.
3. robots.txt를 Cloudflare가 대신 관리하는 설정(Managed robots.txt 또는 Bot Preference Sync)이 AI 로봇을 막는 쪽으로 켜져 있으면 끕니다. 켜 두면 Cloudflare가 우리 robots.txt 앞에 차단 규칙을 덧붙입니다.
4. 브라우저에서 `https://passionstore.kr/robots.txt`를 열어 맨 위가 “# 열정상회는 검색엔진과 AI 검색의 수집을 환영합니다”로 시작하는지 확인합니다. 그 앞에 다른 내용이 붙어 있으면 3번 설정이 켜져 있는 것입니다.

### 네이버 AI 브리핑은 네이버 안의 글을 많이 봅니다

네이버는 AI 브리핑이 참고하는 글의 상당수가 블로그, 카페, 지식iN 같은 네이버 안의 글이라고 밝혔습니다(2026년 5월). 홈페이지만으로는 한계가 있으니 5번 항목의 네이버 블로그를 꼭 함께 운영하세요.

- 상회보 글 한 편마다 블로그 글 한 편을 씁니다. 요점 상자 세 줄과 핵심 문단 하나, 표 하나를 옮기고 “전체 글 보기”로 홈페이지 주소를 겁니다.
- 제목은 홈페이지 글과 조금 다르게 짓습니다. 본문을 통째로 복사하지 않습니다.
- 블로그 소개와 글 끝에 “열정상회는 회비 없이 운영하는 서울의 사업자 모임입니다”를 한 줄로 넣습니다.
- 블로그 주소를 `site.json`의 `contact.naverBlog`에 넣으면 구조화 데이터에 연결되어 같은 단체의 채널로 인식됩니다. 인스타그램, 카카오톡 채널도 같습니다.

## 9. 새 글을 검색엔진에 바로 알리기 (IndexNow)

네이버와 빙은 IndexNow라는 방식으로 “주소가 바뀌었다”는 알림을 받습니다. 검색 로봇이 올 때까지 기다리지 않아도 됩니다.

- 관리자 화면 → **상회보** → **검색엔진에 알리기**를 누르면 홈페이지의 모든 주소를 네이버와 빙에 보냅니다.
- 글을 저장한 뒤 2분쯤 지나 홈페이지에 반영된 다음에 누릅니다. 하루에 한 번이면 충분합니다.
- “접수” 또는 “접수(확인 중)”이 나오면 된 것입니다. 알린다고 반드시 색인되는 것은 아니고, 가져갈지는 검색엔진이 정합니다.
- 확인용 값은 `site.json`의 `indexNowKey`입니다. 비밀 값이 아니며, 같은 이름의 파일이 홈페이지에 자동으로 만들어집니다. 바꾸지 마세요.
- 구글은 IndexNow를 쓰지 않습니다. 구글에는 서치 콘솔의 사이트맵 제출과 URL 검사 → 색인 생성 요청을 씁니다.

## 10. 홈페이지 밖에서 할 일

검색엔진과 AI는 홈페이지 안의 글뿐 아니라 다른 곳에서 이 모임을 어떻게 말하는지도 봅니다.

- **같은 소개 문장을 씁니다.** 블로그, 인스타그램, 카카오톡 채널, 행사 공지에 “열정상회는 사업자·자영업자·프리랜서가 회비 없이 함께하는 서울의 사업자 모임”이라는 문장을 똑같이 씁니다.
- **장날 후기를 남깁니다.** 장날이 열리면 홈페이지 상회보와 블로그에 후기를 올리고, 참석한 분이 자기 채널에 쓴 후기가 있으면 허락을 받아 연결합니다.
- **소개될 곳을 찾습니다.** 지역 소상공인 지원 기관의 모임 안내, 공유 오피스 게시판, 회원이 운영하는 가게의 블로그처럼 실제로 관련 있는 곳에 소개를 부탁합니다. 돈을 내고 링크를 사거나 관련 없는 곳에 주소를 뿌리지 않습니다.
- **검색 유입을 확인합니다.** 관리자 화면 운영 지표의 “들어온 경로”에서 네이버 검색, 구글 검색으로 들어온 방문을 달마다 봅니다.
