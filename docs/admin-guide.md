# 열정상회 관리자 안내서

홈페이지 주소 뒤에 `/admin`을 붙이면 관리자 화면이 열립니다. 예: `https://passionstore.pages.dev/admin`

회장과 운영진이 각자 계정으로 들어와 신청서, 회원 명부, 상단, 장날 일정, 상회보 글을 한곳에서 다룹니다. 검색엔진에는 나오지 않게 막아 두었습니다.

## 1. 화면 구성

| 메뉴 | 하는 일 | 저장되는 곳 |
| --- | --- | --- |
| 오늘 할 일 | 새 신청, 면담 대기, 상단 배정 대기, 회비 확인, 휴회 복귀 같은 일을 한 줄씩 보여 줍니다. 운영 건강 지표도 여기 있습니다. | - |
| 가입 신청 | 홈페이지 가입 신청서. 연락 → 면담 → 승인 → 회원 명부 등록 순서로 처리합니다. | Cloudflare D1 |
| 장날 신청 | 장날 참가 신청과 다음 장날 알림 신청. 참석 확정, 참석, 불참을 표시합니다. | Cloudflare D1 |
| 회원 명부 | 상회원과 사랑방 회원. 상단, 역할, 회비, 휴회, 사업자 확인, 헌장 서약을 관리합니다. | Cloudflare D1 |
| 상단 | 상단 만들기, 회원 배정, 상단장 지정, 모임 기록(날짜, 진행자, 출석). | Cloudflare D1 |
| 장날 일정 | 홈페이지의 장날 일정과 신청서 날짜 목록. | GitHub 저장소(site.json) |
| 상회보 | 글 쓰기, 고치기, 임시 저장, 사진 올리기, 검색 노출 점검. | GitHub 저장소(content/journal) |
| 사이트 정보 | 연락처, 회비, 운영진 소개, 운영 정보, 검색엔진 소유 확인 코드. | GitHub 저장소(site.json) |
| 관리자 계정 | 운영진 계정 추가, 권한 변경, 임시 비밀번호 발급, 사용 중지. (회장 전용) | Cloudflare D1 |
| 활동 기록 | 누가 언제 무엇을 바꿨는지. (회장 전용) | Cloudflare D1 |
| 개인정보 관리 | 보관 기간이 지난 정보 정리, 목록 내려받기(CSV). (회장 전용) | Cloudflare D1 |

GitHub에 저장되는 메뉴는 저장할 때마다 저장소에 기록(커밋)이 하나씩 생기고, Cloudflare가 1~2분 안에 홈페이지를 다시 만듭니다. 기록 메시지 끝에 저장한 사람 이름이 붙습니다.

## 2. 처음 한 번만 하는 설정

모두 Cloudflare 대시보드와 GitHub 웹에서 할 수 있습니다. 명령어는 필요 없습니다.

### 2-1. D1 데이터베이스 만들기와 연결

1. Cloudflare 대시보드 왼쪽 메뉴에서 **Storage & Databases → D1 SQL Database**로 갑니다.
2. **Create**를 누르고 이름을 `passionstore`로 만듭니다. 위치는 자동(가까운 곳)으로 둡니다.
3. **Workers & Pages → passionstore → 설정(Settings) → 바인딩(Bindings)**에서 **추가(Add) → D1 데이터베이스**를 고릅니다.
4. 변수 이름에 `DB`를 적고, 데이터베이스는 방금 만든 `passionstore`를 고른 뒤 저장합니다.

표는 관리자 화면에 처음 들어올 때 자동으로 만들어집니다.

### 2-2. 첫 계정용 설정 키

1. 같은 프로젝트의 **설정 → 변수 및 비밀(Variables and Secrets)**에서 **추가**를 누릅니다.
2. 종류는 **비밀(Secret)**, 이름은 `ADMIN_SETUP_KEY`, 값은 남이 짐작할 수 없는 긴 문장으로 넣습니다.

이 값은 첫 회장 계정을 만들 때 한 번 씁니다. 회장 권한 계정이 하나라도 있으면 첫 계정 만들기 화면은 닫혀 있습니다.

### 2-3. GitHub 연결(장날 일정, 상회보, 사이트 정보용)

1. GitHub 오른쪽 위 프로필 → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. **Repository access**는 **Only select repositories**에서 `passionstore` 하나만 고릅니다.
3. **Permissions → Repository permissions → Contents**를 **Read and write**로 바꿉니다. 다른 권한은 건드리지 않습니다.
4. 만료일은 1년 안으로 정합니다. 만료되기 전에 같은 방법으로 새로 만들어 바꿔 넣으면 됩니다.
5. 만든 토큰을 Cloudflare **설정 → 변수 및 비밀**에 종류 **비밀(Secret)**, 이름 `GITHUB_TOKEN`으로 넣습니다.

저장소 이름이나 기본 브랜치를 바꿨다면 일반 변수로 `GITHUB_REPO`(예: `naadaa87/passionstore`), `GITHUB_BRANCH`(예: `main`)를 추가합니다. 바꾸지 않았다면 넣지 않아도 됩니다.

### 2-4. 다시 배포하고 첫 계정 만들기

1. **배포(Deployments)** 탭에서 가장 최근 배포의 **다시 시도(Retry deployment)**를 누릅니다. 바인딩과 변수는 다시 배포해야 적용됩니다.
2. 배포가 끝나면 `/admin`에 들어가 설정 키, 이름, 이메일, 비밀번호를 넣고 첫 회장 계정을 만듭니다.
3. 로그인한 뒤 **관리자 계정**에서 운영진 계정을 추가합니다. 화면에 한 번만 보이는 임시 비밀번호를 본인에게 직접 전하면, 첫 로그인 때 각자 새 비밀번호로 바꿉니다.

부회장처럼 회장 권한을 하나 더 둘 사람이 있다면 그 계정은 **회장 권한**으로 만들어 두세요. 회장 계정 비밀번호를 잊었을 때 다른 회장 권한 계정에서 임시 비밀번호를 발급할 수 있습니다.

### 2-5. (선택) 한 겹 더 잠그기

자체 도메인을 연결한 뒤에는 Cloudflare Zero Trust의 **Access**로 `/admin`과 `/api/admin` 경로에 이메일 인증을 한 겹 더 걸 수 있습니다. 관리자 화면 자체에도 로그인, 15분 동안 10번 실패 시 잠금, 12시간 로그인 유지, 다른 사이트에서 보낸 요청 차단이 들어 있어 꼭 필요하지는 않습니다.

## 3. 권한

| | 운영진 권한 | 회장 권한 |
| --- | --- | --- |
| 신청서 보기, 상태와 메모 바꾸기, 회원 명부에 올리기 | ○ | ○ |
| 회원 정보 고치기, 상단 만들기와 배정, 모임 기록 | ○ | ○ |
| 장날 일정 고치기, 상회보 쓰기와 고치기, 사진 올리기 | ○ | ○ |
| 사이트 정보(연락처, 회비, 운영진 소개 등) 바꾸기 | | ○ |
| 신청서, 회원 정보, 상회보 글 삭제 | | ○ |
| 관리자 계정, 활동 기록, 개인정보 정리, 목록 내려받기 | | ○ |

운영진 임기가 끝나면 계정을 지우지 말고 **사용 중지**로 바꿉니다. 활동 기록은 그대로 남습니다.

## 4. 이렇게 씁니다

### 가입 신청

1. **새 신청**은 접수한 순서대로 먼저 연락하고 상태를 **연락함**으로 바꿉니다.
2. 면담 날짜를 잡으면 **면담 예정**, 면담을 마치고 함께하기로 하면 **가입 승인**으로 바꿉니다. 메모에 연락한 날짜와 면담 내용을 짧게 남깁니다.
3. **회원 명부에 올리기**를 누르면 신청서 내용이 그대로 명부로 옮겨지고 상태가 **등록 완료**가 됩니다. 이때 상단을 바로 고르거나 나중에 배정할 수 있습니다. 희망 시간대가 맞는 상단에는 “희망 시간대” 표시가 붙습니다.

### 상단

- 배정을 기다리는 상회원은 **상단** 화면 위쪽과 **오늘 할 일**에 시간대별로 나옵니다. 한 시간대에 다섯 명 이상 모이면 새 상단을 열자는 알림이 뜹니다.
- 상단장은 그 상단에 속한 활동 회원 가운데서 고릅니다. 상단장으로 지정하면 회원 역할에 “상단장”이 자동으로 붙습니다.
- 모임을 마칠 때마다 **모임 기록하기**로 날짜, 진행한 사람, 출석을 남깁니다. 회장이 진행한 모임이면 “회장이 진행했습니다”에 체크합니다.
- 메모에는 회원의 사업 정보를 꼭 필요한 만큼만 적습니다(헌장 2조).

### 장날

1. **장날 일정**에서 날짜, 시간, 장소, 주제를 넣고 상태를 정합니다. **신청 받는 중**이면 홈페이지 신청서에 날짜가 나타나고, **신청 준비 중**이면 일정만 보입니다.
2. 신청이 들어오면 **장날 신청**에서 **참석 확정**으로 바꾸고 장소를 안내합니다. 장날이 끝나면 **참석**이나 **불참**으로 정리합니다.
3. 지난 일정은 **지난 일정 정리**로 한꺼번에 뺄 수 있습니다. 지난 날짜는 원래 홈페이지에 나오지 않으니 급하지 않습니다.

### 상회보

- **새 글 쓰기**에서 제목, 글 주소(영문), 검색 결과 설명, 키워드를 넣고 본문을 씁니다. 오른쪽(휴대폰은 아래쪽) **검색 노출 점검**이 제목 길이, 설명 길이, 소제목 수, 다른 글과 키워드가 겹치는지 바로 알려 줍니다.
- 아직 공개하지 않을 글은 **임시 저장**에 체크하고 저장합니다. 홈페이지에는 보이지 않습니다.
- **대표 그림**에서 열정상회 그림 가운데 하나를 고르거나, **사진을 올려서 쓰기**로 직접 찍은 사진을 올립니다. 대표 그림은 글 머리, 상회보 목록, 카카오톡·SNS 공유 미리보기에 나옵니다. 직접 올린 사진이면 “대표 사진 설명”도 적어 주세요.
- **사진 넣기**를 누르면 사진을 가로 1600px 이하로 줄여 올리고 본문에 넣어 줍니다. 괄호 앞 `[ ]` 안에 사진 설명을 꼭 적어 주세요. 검색엔진과 화면 낭독기가 이 설명을 읽습니다.
- 글 주소는 나중에 바꿀 수 없습니다. 주소를 바꾸면 이미 공유된 링크가 깨지기 때문입니다.
- 키워드는 `docs/seo-guide.md`의 키워드 지도에서 다른 글과 겹치지 않는 말을 고릅니다.

### 운영 건강

**오늘 할 일** 오른쪽의 지표는 열정상회가 회장 한 사람에게 기대지 않고 돌아가는지 보는 숫자입니다.

- **회장이 직접 진행한 상단 모임**: 최근 90일 모임 가운데 회장이 진행한 비율. 낮을수록 상단장과 회원이 모임을 이끌고 있다는 뜻입니다.
- **가입 신청 경로**: “회장·운영진을 통해” 들어온 신청이 절반을 넘으면 장날, 상회보, 회원 추천으로 들어오는 길을 넓힐 때입니다.
- **상단 모임 출석률**: 최근 90일 출석 기록 기준입니다.

## 5. 개인정보 관리

- 처리방침에 따라 가입하지 않은 신청자의 정보는 신청일로부터 6개월 뒤, 탈퇴한 회원의 정보는 지체 없이 파기합니다.
- 한 달에 한 번 **개인정보 관리 → 지금 정리하기**를 눌러 주세요. 6개월이 지난 미가입 신청서와 탈퇴 회원 정보(출석 기록, 가입 신청서 포함)가 지워집니다.
- 회원이 탈퇴하면 회원 정보에서 상태를 **탈퇴**로 바꾼 뒤, 회원 정보 화면의 **회원 정보 완전 삭제**로 바로 지울 수도 있습니다.
- 내려받은 CSV 파일에는 연락처가 들어 있습니다. 쓰고 나면 컴퓨터에서 지워 주세요. 내려받은 기록은 활동 기록에 남습니다.

## 6. 문제가 생겼을 때

| 화면에 보이는 것 | 할 일 |
| --- | --- |
| “데이터베이스를 연결해 주세요” | 2-1의 바인딩 이름이 정확히 `DB`인지 확인하고 다시 배포합니다. |
| “첫 계정을 만들 준비가 필요합니다” | 2-2의 `ADMIN_SETUP_KEY`를 넣고 다시 배포합니다. |
| 장날 일정, 상회보, 사이트 정보 화면에 GitHub 연결 안내가 나옴 | 2-3의 `GITHUB_TOKEN`을 넣고 다시 배포합니다. |
| “GitHub 토큰이 만료되었거나 권한이 부족합니다” | 토큰을 새로 만들어 `GITHUB_TOKEN` 값을 바꾸고 다시 배포합니다. Contents 권한이 Read and write인지 확인합니다. |
| “그사이 다른 곳에서 바뀌었습니다” | 다른 사람이 같은 파일을 먼저 저장했습니다. 화면을 새로 고친 뒤 다시 고쳐 저장합니다. |
| “로그인 시도가 너무 많습니다” | 15분 뒤에 다시 시도합니다. |
| 운영진이 비밀번호를 잊음 | 회장 계정의 **관리자 계정 → 임시 비밀번호**로 새로 발급합니다. |
| 회장 계정 비밀번호를 잊음 | 다른 회장 권한 계정이 있으면 거기서 임시 비밀번호를 발급합니다. 없다면 아래 순서를 따릅니다. |

**회장 권한 계정이 하나도 남지 않았을 때**

1. Cloudflare 대시보드 **D1 SQL Database → passionstore → 콘솔(Console)**로 갑니다.
2. 아래 한 줄을 실행합니다. 회장 권한 계정만 지워지고, 운영진 계정과 신청서, 회원 명부는 그대로 남습니다.

   ```sql
   DELETE FROM admins WHERE role = 'owner';
   ```

3. `/admin`에 들어가면 첫 계정 만들기 화면이 다시 열립니다. `ADMIN_SETUP_KEY` 값으로 회장 계정을 새로 만듭니다.

## 7. 개발 메모

- 화면: `admin/index.html`, `admin/admin.css`, `admin/admin.js`. 빌드(`node tools/build.js`) 때 `public/admin/`으로 복사되고, 상회보 미리보기용으로 `tools/md.js`가 `public/admin/md.js`로 함께 만들어집니다. `public/admin/`은 직접 고치지 않습니다.
- 서버: `functions/api/admin/[[path]].js`가 `server/admin-api.js`를 부릅니다. `server/db.js`(D1 표), `server/auth.js`(비밀번호 PBKDF2, 세션 쿠키), `server/github.js`(저장소 파일 읽기·쓰기), `server/http.js`(응답, 요청 검사).
- 신청서 접수(`functions/api/apply.js`)는 D1이 연결되어 있으면 `applications` 표에 저장하고, 구글 시트 웹훅이나 KV가 설정되어 있으면 그곳에도 함께 보냅니다.
- 변수: `DB`(D1 바인딩), `ADMIN_SETUP_KEY`, `GITHUB_TOKEN`, 선택 `GITHUB_REPO`, `GITHUB_BRANCH`, `GITHUB_API`(로컬 시험용 주소 바꾸기).
- 로컬 시험: `npx wrangler pages dev public --d1=DB --binding ADMIN_SETUP_KEY=아무값 --binding GITHUB_TOKEN=...`
